## Why

`codever-ui` still ships Bootstrap 4: the stylesheet bundled from `node_modules` is 4.6.2 while `src/index.html` loads Bootstrap's JavaScript 4.4.1 plus jQuery and Popper from three external CDN tags, so the CSS and JS versions do not even agree. Bootstrap 4 is unmaintained, and the CDN scripts keep jQuery as a runtime dependency that nothing in the codebase actually calls. Bootstrap 5.3.x is the current supported line and its bundle drops jQuery entirely.

## What Changes

- `codever-ui` dependency `bootstrap` moves from `^4.6.2` to the 5.3.x line (latest published: 5.3.8), with `package-lock.json` regenerated by npm rather than hand-edited.
- **BREAKING** for the UI's own markup: Bootstrap 4 class names and plugin attributes used in 90 Angular templates are migrated to their Bootstrap 5 equivalents (for example `ml-*`/`mr-*` -> `ms-*`/`me-*`, `badge-pill` -> `rounded-pill`, `badge-success` -> `bg-success`, `sr-only` -> `visually-hidden`, `data-toggle`/`data-target` -> `data-bs-toggle`/`data-bs-target`).
- The three external `<script>` tags in `src/index.html` (jQuery 3.4.1 slim, Popper 1.16, Bootstrap 4.4.1) are removed. Bootstrap 5's bundle (`bootstrap.bundle.min.js`, which already includes Popper) is loaded from `node_modules` through the Angular builder, so the UI has no external script dependencies.
- The direct `jquery` dependency is removed from `codever-ui`, since verification shows no jQuery call sites outside Bootstrap 4's CDN JavaScript.
- The dead `$icon-font-path` assignment in `src/scss/_variables.scss` (it points at the uninstalled `bootstrap-sass` package and at Glyphicons, which Bootstrap 4 and later do not ship) is removed.
- Existing Codever layout, Angular Material integration, and all UI route paths stay as they are. No component is redesigned.

## Capabilities

### New Capabilities

- `ui-styling`: the UI's styling and interaction baseline - which Bootstrap line `codever-ui` delivers, that its CSS is served from a single project-built source, that Bootstrap's markup-driven interactive components keep working without jQuery or external CDN scripts, and that existing class contracts in the UI continue to render.

### Modified Capabilities

None. `legacy-dashboard-route-redirects` describes SPA route behavior, which this change does not alter.

## Impact

**Affected app**: `codever-ui` only. `codever-api` is untouched.

**Routes**: no route definitions change. The migration affects templates rendered by both unauthenticated/public areas (homepage, about, howto, privacy, terms, register, public user profiles, shareable bookmark and note details) and personal/authenticated areas (dashboard, my-bookmarks, my-notes, my-collections, user settings, search results). Authenticated rendering still depends on the existing Keycloak flow; nothing in the auth path is modified.

**APIs**: none. No endpoint, request shape, response shape, error class, or HTTP status changes.

**Mongoose models**: none. No schema, field, or index changes.

**Dependencies**:
- `bootstrap` `^4.6.2` -> `5.3.x` (CSS artifact grows from 162 KB to roughly 230 KB minified; the exact figure is measured during implementation).
- `jquery` `^3.5.1` removed.
- `popper.js` `1.16.1` is present transitively but is only used from the CDN today; Bootstrap 5's bundle carries its own Popper, so no direct dependency is added.
- `package-lock.json` regenerated.

**Runtime/network**: three third-party CDN origins (code.jquery.com, cdn.jsdelivr.net, stackpath.bootstrapcdn.com) are removed from the page load path, which also makes the production service-worker/cache story deterministic instead of depending on external hosts.

**Documentation**: `apps/codever-ui/README.md` and any repo notes that describe Bootstrap 4 or the CDN script setup need updating. `update-bootstrap/PLAN.md` is the planning input for this change; it is deliberately left as-is, and the corrections to its stale baseline (Angular 16 claim, non-existent duplicate stylesheet, non-existent Bootstrap Sass import, `@extend .float-right` that does not exist) are recorded in `design.md`.
